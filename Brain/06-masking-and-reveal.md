# 06 — الحجب والكشف والدفع ★ المنطق الجوهري

> هذا هو المنتج. كل ما عداه بنية تحتية. اقرأه كاملاً قبل لمس أي كود يمسّ الملفّات.

## 1. قاعدة الوصول الجوهرية

> يُخدَم الملفّ من الـ API في صورةٍ **محجوبة افتراضياً**، ولا تُكشَف الحقول الحسّاسة إلّا إذا وُجِد سجلّ `candidate_reveals` **صالح ومكتمل** يربط (الشركة الطالبة ← الموظّف المطلوب).

الحجب **ليس حالة عرض**، بل **حالة بيانات**. الخادم لا يملك خياراً: إن لم يوجد سجلّ كشف صالح، فالحقل الحسّاس **غير موجود في الاستجابة**.

## 2. ما الخطأ الذي يجب ألّا نرتكبه

هذه قائمة الأخطاء التي تُفشل المنتج كلّه. راجعها في كل مراجعة كود.

| ❌ خطأ | لماذا كارثي |
|---|---|
| إرسال `name` وتشويشه بـ CSS `blur()` | يُقرأ بنقرة في أدوات المطوّر. **هكذا يعمل نموذج التصميم — لا تنسخه.** |
| إرسال `initials: "أ.ك"` | الحروف الأولى + المسمّى + المدينة + سنوات الخبرة = تحديد هويّة في سوقٍ بحجم قطر. |
| إرسال `name: null` بينما يُرسَل للمكشوف `name: "أحمد"` | يكشف بنية الحقل ويسهّل الاستنتاج. الحقل **يُحذف**، لا يُفرَّغ. |
| تنجيم النصّ `أ***د` في الخادم | يسرّب الطول والحرف الأول والأخير. |
| استخدام `id` تسلسلي في المسار العامّ | يتيح تعداد الملفّات (`/candidates/1,2,3…`). |
| السماح بالبحث بالاسم | استعلام `?q=أحمد` يكشف وجود «أحمد» في النتائج ← تسريب عبر الاستعلام. |
| توليد الصورة الرمزية من الاسم في الواجهة | نفس تسريب الحروف الأولى. |
| ترك رفع السير الذاتية على قرص `public` | رابط مباشر يتجاوز كل الحجب. |
| كشف `current_employer` للشركة صاحبة العمل | تدمير سرّية الموظّف — وهو أخطر ضرر بشري في المنتج. |

## 3. الحقول المحجوبة — الاقتراح الافتراضي

⚠️ **معلّق على إقرارك** (القرار #3 في [`00-vision-and-scope.md`](00-vision-and-scope.md)).

كل صفّ هنا **إعداد** في `settings.masking.fields`، قابل للتفعيل والتعطيل لكل حقل من اللوحة.

| الحقل | محجوب افتراضياً؟ | السبب |
|---|---|---|
| `name` | ✅ نعم | معرّف مباشر |
| `initials` | ✅ نعم | معرّف شبه مباشر (انظر §2) |
| `avatar` | ✅ نعم | معرّف مباشر |
| `phone` | ✅ نعم | قناة الاتصال — جوهر المنتج |
| `email` | ✅ نعم | قناة الاتصال |
| `current_employer` | ✅ نعم | يحمي الموظّف من صاحب عمله |
| `attachments` (CV والشهادات) | ✅ نعم | تحوي الاسم داخلها حتماً |
| `linkedin` / روابط | ✅ نعم | معرّف مباشر |
| — | — | — |
| `ref` (كفاءة #4821) | ❌ لا | معرّف عامّ عشوائي غير معرِّف |
| `title` (المسمّى الوظيفي) | ❌ لا | جوهر العرض |
| `field` (المجال) | ❌ لا | أساس الفلترة |
| `years_experience` | ❌ لا | أساس الفلترة |
| `city` | ❌ لا | أساس الفلترة |
| `skills` | ❌ لا | جوهر العرض |
| `employment_status` | ❌ لا | جوهر العرض |
| `expected_salary` | ❌ لا | جوهر العرض (يظهر في التصميم `1a`) |
| `experiences` (بلا اسم جهة العمل الحالية) | ❌ لا | جوهر العرض |

> **مفارقة يجب حسمها معك:** حجب `attachments` يعني أن الشركة **لا ترى السيرة الذاتية قبل الدفع**. هذا يقلّل ثقتها ويرفع احتمال الاسترداد. البديل: توليد **نسخة مُنقّحة تلقائياً (redacted CV)** تُزال منها بيانات التعريف وتُعرض قبل الدفع. هذه ميزة غير تافهة تقنياً (تحليل PDF). **الاقتراح للـ MVP:** لا نعرض CV قبل الكشف إطلاقاً، ونعوّض بعرض غنيّ للخبرات والمهارات. التنقيح الآلي مؤجّل. ينتظر قرارك.

## 4. آلة الحجب — التصميم البرمجي

### `ProfileVisibilityService`

مصدر الحقيقة الوحيد لسؤال: *أي حقول يرى هذا المشاهد من هذا الملفّ؟*

```php
final class ProfileVisibilityService
{
    public function visibleFields(?User $viewer, EmployeeProfile $profile): FieldSet
    {
        // 1) صاحب الملفّ يرى كل شيء.
        if ($viewer?->id === $profile->user_id) {
            return FieldSet::all();
        }

        // 2) من يملك صلاحية الإشراف يرى كل شيء (ويُسجَّل ذلك في التدقيق).
        if ($viewer?->can('profile.moderate')) {
            return FieldSet::all();
        }

        // 3) قاعدة عمى صاحب العمل — تسبق كل شيء آخر.
        //    الشركة لا ترى ملفّ موظّفها الحالي أصلاً، فضلاً عن كشفه.
        if ($this->isCurrentEmployer($viewer, $profile)) {
            throw new ProfileNotVisibleException();   // 404، لا 403
        }

        // 4) هل توجد عملية كشف صالحة لهذا الزوج؟
        if ($this->reveals->hasValidReveal($viewer?->company, $profile)) {
            return FieldSet::all();
        }

        // 5) الافتراضي: محجوب. الحقول المحجوبة تأتي من الإعدادات.
        return FieldSet::all()->except(
            $this->settings->get('masking.fields')
        );
    }
}
```

**لماذا `404` لا `403` في قاعدة عمى صاحب العمل؟** لأن `403` تعني «هو موجود لكن ممنوع» — وهذا وحده يخبر الشركة أن موظّفها يبحث عن عمل. **الوجود نفسه سرّ.** يجب أن يبدو الملفّ كأنه غير موجود.

### `MaskedProfileResource`

الحاجز الأخير قبل الشبكة. لا يبني الاستجابة من النموذج، بل من `FieldSet`:

```php
public function toArray($request): array
{
    $fields = app(ProfileVisibilityService::class)
        ->visibleFields($request->user(), $this->resource);

    return $fields->filter([
        'ref'               => $this->ref,
        'title'             => $this->title,
        'field'             => LookupResource::make($this->field),
        'years_experience'  => $this->years_experience,
        'city'              => $this->city,
        'employment_status' => LookupResource::make($this->employmentStatus),
        'skills'            => $this->skills->pluck('name'),
        'expected_salary'   => $this->salaryRange(),
        'is_revealed'       => $fields->has('name'),
        'reveal_fee'        => $this->settings->get('reveal.fee'),

        // هذه تختفي كلّياً من المصفوفة إن لم تكن في FieldSet:
        'name'              => $this->user->name,
        'initials'          => $this->initials(),
        'phone'             => $this->user->phone,
        'email'             => $this->user->email,
        'current_employer'  => $this->current_employer,
        'attachments'       => AttachmentResource::collection($this->attachments),
    ]);
}
```

`FieldSet::filter()` **يحذف المفاتيح** غير المسموحة، ولا يُفرّغها. اختبار الوحدة يؤكّد:
`$this->assertArrayNotHasKey('name', $response)` — لا `assertNull`.

### حماية الاستعلام

الحجب في الاستجابة لا يكفي. **الاستعلام نفسه قناة تسريب:**

- مسار البحث `?q=` يبحث في **الحقول غير المحجوبة فقط** (المسمّى، المهارات، المجال). لا يمسّ `users.name` أبداً.
- الترتيب لا يجوز أن يكون بحقل محجوب.
- عدّاد النتائج يُحسب **بعد** تطبيق عمى صاحب العمل، وإلّا سُرّب وجود الملفّ عبر فرق العدد.

## 5. المعرّف العامّ (`ref`)

في التصميم: `كفاءة #4821`. في الإنتاج:

- عمود `ref` منفصل عن المفتاح الأساسي، **عشوائي وغير متسلسل**، فريد، مفهرَس.
- التنسيق: 8 محارف من أبجدية آمنة (بلا `0/O/1/I`)، يُعرض بصيغة `كفاءة #XXXXXXXX`.
- كل مسارات الـ API العامّة تستقبل `ref` لا `id` (route model binding على `ref`).
- الرقم `4821` في التصميم مجرّد بيانات وهمية — لا يُنسخ كنمط تسلسلي.

## 6. تدفّق الكشف

```
الشركة تتصفّح  ──►  بطاقات محجوبة (بلا اسم ولا تواصل — غائبة من الـ JSON)
       │
       ▼
تضغط «كشف الهوية · ٧٥ ر.ق»
       │
       ▼
POST /api/v1/candidates/{ref}/reveal      [Idempotency-Key مطلوب]
       │
       ├──► فحص Policy: هل تملك candidate.reveal؟
       ├──► فحص عمى صاحب العمل ──► 404
       ├──► فحص كشف سابق مكتمل ──► 200 (لا خصم مزدوج)
       │
       ▼
يقرأ نموذج الدفع من الإعدادات: settings('billing.model')
       │
       ├─ pay_per_reveal ─► إنشاء payment (pending) + reveal (pending)
       │                    └──► إعادة توجيه لبوّابة الدفع
       │
       └─ subscription ───► قفل صفّ الرصيد (SELECT … FOR UPDATE)
                            ├─ رصيد كافٍ ──► خصم + reveal (completed) فوراً
                            └─ رصيد نافد ─► 402 Payment Required
       │
       ▼
[بوّابة الدفع] ──► webhook: payment.succeeded
       │
       ▼
معاملة قاعدة بيانات واحدة:
   payment.status = paid
   reveal.status  = completed,  revealed_at = now()
   audit_log(actor: company, action: candidate.revealed, subject: profile)
       │
       ▼
الـ API يفكّ الحجب لهذا الزوج فقط  ──►  ظهور الاسم وبيانات التواصل
       │
       ▼
(إن كان الإعداد مفعّلاً) إشعار الموظّف: «شركةٌ اطّلعت على ملفّك»
```

### الضمانات الملزمة

| الضمان | كيف يُفرَض |
|---|---|
| **لا خصم مزدوج** | فهرس فريد على `(company_id, employee_profile_id)` حيث `status = completed` + فحص قَبْلي + `Idempotency-Key` على الطلب. |
| **لا كشف بلا دفع** | `reveal.status = completed` لا يُكتب إلّا داخل معاملة الـ webhook، ولا يكتبه المتحكّم أبداً. |
| **لا دفع بلا كشف** | webhook فاشل الكتابة ← يُعاد المحاولة (queue retry) ← تنبيه للمشرف بعد N محاولات. |
| **لا سباق (race)** | خصم رصيد الاشتراك داخل `lockForUpdate()`. |
| **webhook موثوق** | التحقّق من توقيع البوّابة + `provider_ref` فريد يمنع إعادة التشغيل (replay). |

### حالات `candidate_reveals`

```
pending ──► completed ──► refunded
   │
   └──► failed  (فشل الدفع أو انقضت المهلة)
```

`pending` **لا يفكّ الحجب**. فقط `completed`.

## 7. الاسترداد

⚠️ **السياسة معلّقة على قرارك** (القرار #2). المنطق البرمجي جاهز أياً كانت:

```php
settings('refund.enabled')          // bool
settings('refund.window_days')      // int   — خلال كم يوماً
settings('refund.percentage')       // int   — نسبة الاسترداد
settings('refund.trigger')          // enum  — employee_declined | no_response | manual_only
```

عند الاسترداد: `reveal.status = refunded` ← **ويُعاد الحجب فوراً**. الشركة رأت الاسم أصلاً، لكن إبقاء الوصول بعد استرداد المال خطأ منطقي وقانوني.

> **سؤال يحتاج حسمك:** إن استُرِدّ المبلغ ثم أرادت الشركة كشف المرشّح نفسه ثانيةً — أتدفع من جديد؟ **الاقتراح: نعم.** الفهرس الفريد يُبنى على `(company_id, employee_profile_id, status)` بحيث يسمح بسجلّ `completed` جديد بعد `refunded`.

## 8. قواعد الخصوصية الإضافية (إعدادات)

| الإعداد | الأثر |
|---|---|
| `privacy.employer_blind` | تفعيل قاعدة عمى صاحب العمل (§4). **مفعّل افتراضياً.** |
| `privacy.notify_on_reveal` | إشعار الموظّف عند كشف ملفّه. |
| `privacy.allow_employee_blocklist` | يسمح للموظّف بحجب شركات بعينها من رؤية ملفّه. |
| `privacy.profile_visibility_default` | `public` \| `hidden` للملفّات الجديدة. |

## 9. الاختبارات الملزمة لهذه الوحدة

لا تُعتمد مرحلة الحجب (م4) قبل مرور هذه الاختبارات:

1. شركة بلا كشف تطلب القائمة → الاستجابة **لا تحوي مفاتيح** `name`/`phone`/`email`/`initials`.
2. شركة بلا كشف تطلب ملفّاً بالـ `ref` → نفس النتيجة.
3. شركة **بكشف مكتمل** → المفاتيح موجودة وقيمها صحيحة.
4. شركة بكشف `pending` → المفاتيح **غائبة**.
5. شركة بكشف `refunded` → المفاتيح **غائبة**.
6. شركة تطلب ملفّ موظّفها الحالي → `404` (لا `403`).
7. البحث بـ `?q=` باسم موظّف موجود → **لا يُرجعه**.
8. تعداد `ref` عشوائياً → لا يصيب.
9. كشف مزدوج متزامن (طلبان معاً) → دفعة واحدة، سجلّ واحد.
10. تعديل `masking.fields` من اللوحة → ينعكس فوراً على الاستجابة دون نشر كود.
11. طلب مرفق CV مباشرةً بالرابط دون كشف → `403`.
12. كل كشف ناجح ← صفّ في `audit_logs`.
