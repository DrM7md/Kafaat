# 08 — مراحل التطوير

## مبدأ التقسيم

المراحل مرتّبة بـ **تبعية تقنية** لا بأهمّية تجارية. لا تُبدأ مرحلة قبل اكتمال ما تعتمد عليه. كل مرحلة تنتهي بـ **بوّابة موافقة**: لا انتقال للتالية قبل مرور معايير القبول وموافقتك.

**العُقدة المركزية:** م4 (الحجب والتصفّح) هي المرحلة التي يصبح فيها المنتج منتجاً. كل ما قبلها تمهيد، وكل ما بعدها بناء عليها. وهي تعتمد على م2 (الإعدادات) و م3 (الملفّات) معاً.

```
م0 الأساس
 └─► م1 المصادقة و RBAC
      └─► م2 محرّك الإعدادات
           └─► م3 الملفّات المهنية
                └─► ★ م4 الحجب والتصفّح ★   ← هنا يولد المنتج
                     └─► م5 الكشف والدفع    ← هنا يولد الإيراد
                          ├─► م6 التدقيق والإشعارات
                          ├─► م7 لوحة المشرف
                          └─► م8 الامتثال
                               └─► م9 الصقل والإطلاق
```

## م0 — الأساس (Foundation)

**الهدف:** مشروعان يعملان، وأدوات الجودة تحرس منذ أول commit.

**المُخرجات:**
- `api/` — Laravel، MySQL، Sanctum، Spatie، Pest، Pint، Larastan (level 7+).
- `web/` — React 19 + TS + Vite + Tailwind (RTL) + React Router + TanStack Query.
- رموز التصميم من [`02-design-system.md`](02-design-system.md) في `tokens.css`، والخطوط الثلاثة محمّلة.
- `.env.example` للطرفين، CORS مضبوط، مسار `GET /api/v1/health` يعمل.
- مستودع git مستقلّ لـ `Kafaat/` + `.gitignore` + hooks.

**معايير القبول:**
- ✅ `php artisan test` يمرّ · `pint --test` نظيف · `larastan` نظيف.
- ✅ `npm run build` نظيف · `tsc --noEmit` نظيف.
- ✅ الواجهة تعرض صفحةً بالخطّ والألوان الصحيحة، RTL سليم.
- ✅ إصدار Laravel المثبَّت مُسجَّل في [`01-architecture.md`](01-architecture.md).

**شاشات UI مطلوبة:** لا شيء.

## م1 — المصادقة و RBAC

**يعتمد على:** م0

**الهدف:** «من أنت» و«ماذا يجوز لك» — مبنيّان صحيحاً من البداية، لأن إصلاحهما لاحقاً يعني إعادة كتابة كل شيء.

**المُخرجات:**
- `users` بـ `type` + تسجيل الطرفين + Sanctum.
- `PermissionSeeder` (كتالوج [`04-rbac.md`](04-rbac.md)) + `RoleSeeder` — **قابلان لإعادة التشغيل**.
- `Gate::before` للمشرف العام — الموضع الوحيد الذي يُذكر فيه اسم دور.
- `GET /me` يُعيد الصلاحيات الفعّالة (دور + استثناءات فردية، محسوبة في الخادم).
- مكوّن `<Can>` + `<ProtectedRoute>` في React.

**معايير القبول:** الاختبارات التسعة في [`04-rbac.md`](04-rbac.md) §8 تمرّ.

**بوّابة قرار:** إقرار كتالوج الصلاحيات والأدوار الافتراضية (القرار #4).

**شاشات UI مطلوبة:** ⬜ تسجيل الدخول · ⬜ تسجيل موظّف · ⬜ تسجيل شركة

## م2 — محرّك الإعدادات

**يعتمد على:** م1

**الهدف:** قبل أن نكتب قاعدة عملٍ واحدة، نبني المكان الذي تعيش فيه. **هذه المرحلة تسبق الملفّات عمداً** — لأن قواعد الحجب (م4) تقرأ منها، ولو بنيناها بعدها لكتبنا قيماً ثابتة ثم رجعنا نقتلعها.

**المُخرجات:**
- `settings` + `SettingsRepository` مع الكاش والتصبيب والتدقيق.
- `lookups` + بذورها (الحالات الثلاث بألوانها، المجالات، مدن قطر).
- `GET /settings/public` · `PUT /admin/settings`.
- دالّة `settings()` العامّة.
- كتالوج [`05-settings-engine.md`](05-settings-engine.md) مبذور كاملاً.

**معايير القبول:** الاختبارات السبعة في [`05-settings-engine.md`](05-settings-engine.md) §6 تمرّ. تعديل إعدادٍ من الـ API ينعكس على الطلب التالي بلا نشر كود.

**شاشات UI مطلوبة:** لا شيء (اللوحة في م7).

## م3 — الملفّات المهنية

**يعتمد على:** م2

**الهدف:** الموظّف يبني ملفّه. الشركة تبني ملفّها. لا تصفّح بعد.

**المُخرجات:**
- `employee_profiles` (بـ `ref` عشوائي) · `company_profiles` · `skills` · `experiences` · `educations`.
- `attachments` على **قرص خاص** + `AttachmentPolicy` + بثّ عبر مسار محروس.
- رفع CV، نشر/سحب الملفّ، حساب `completeness`.
- `current_employer_company_id` + النصّ التوضيحي للموظّف.

**معايير القبول:**
- ✅ `ref` عشوائي وفريد ولا يمكن تخمينه.
- ✅ **لا رابط مباشر لمرفق يعمل** بلا Policy — اختبار صريح.
- ✅ الموظّف يرى ملفّه كاملاً، ولا أحد غيره يراه بعد.

**شاشات UI مطلوبة:** ⬜ بناء الملف المهني · ⬜ رفع CV · ⬜ ملفّ الشركة

## م4 — ★ الحجب والتصفّح ★

**يعتمد على:** م2 + م3

**الهدف:** **هنا يولد المنتج.** الشركة ترى كفاءات حقيقية، ولا ترى أسماءها.

**المُخرجات:**
- `ProfileVisibilityService` — مصدر الحقيقة الوحيد لسؤال «أي حقول يرى؟».
- `MaskedProfileResource` — الحاجز الأخير قبل الشبكة.
- قاعدة **عمى صاحب العمل** (`404` لا `403`).
- `GET /candidates` بالبحث والفلترة — **البحث لا يمسّ الاسم**.
- `GET /candidates/{ref}`.
- شاشة التصفّح بمعالجة **`1a`** + `<CandidateCard>` + `<MaskedAvatar>` + `<StatusBadge>` + `<FilterBar>`.

**معايير القبول — الاثنا عشر اختباراً في [`06-masking-and-reveal.md`](06-masking-and-reveal.md) §9، بلا استثناء.**

أهمّها: `assertArrayNotHasKey('name', $response)` — **لا `assertNull`**.

**بوّابة قرار:** إقرار قائمة الحقول المحجوبة (القرار #3) + ADR-009.

**شاشات UI:** ✅ **متوفّرة** (`1a` معتمدة) · ⬜ صفحة الملفّ المفصّل

> هذه المرحلة الوحيدة التي نملك تصميمها كاملاً اليوم.

## م5 — الكشف والدفع

**يعتمد على:** م4

**الهدف:** **هنا يولد الإيراد.** وهنا أخطر شيفرة في المشروع — المال والتزامن معاً.

**المُخرجات:**
- `candidate_reveals` + `payments`.
- `RevealService` — تدفّق [`06`](06-masking-and-reveal.md) §6 كاملاً.
- تكامل بوّابة دفع واحدة + webhook بتحقّق توقيع ومنع إعادة تشغيل.
- `Idempotency-Key` إلزامي على مسار الكشف.
- تجميد السعر (ADR-006).
- الاسترداد + إعادة الحجب (ADR-010).

**معايير القبول:**
- ✅ **لا خصم مزدوج** — اختبار طلبين متزامنين.
- ✅ **لا كشف بلا دفع** — `pending` لا يفكّ الحجب.
- ✅ **لا دفع بلا كشف** — webhook فاشل يُعاد.
- ✅ webhook مُعاد التشغيل مرّتين ← أثر واحد.
- ✅ `refunded` ← إعادة الحجب فوراً.
- ✅ السعر المخزَّن لا يتغيّر بتغيير الإعداد.

**بوّابات قرار:** بوّابة الدفع (#5) · سياسة الاسترداد (#2).

**شاشات UI مطلوبة:** ⬜ **تدفّق الدفع** (الأولوية القصوى) · ⬜ تأكيد الكشف · ⬜ «كشوفاتي»

## م6 — التدقيق والإشعارات

**يعتمد على:** م5

**المُخرجات:**
- `audit_logs` إلحاقيّ + `Auditable` trait على كل فعل حسّاس.
- `profile.viewed_as_moderator` — تسجيل استخدام صلاحية الإشراف.
- إشعار الموظّف عند كشف ملفّه (خلف `privacy.notify_on_reveal`).

**معايير القبول:** كل فعل 🔴 حرج في [`04-rbac.md`](04-rbac.md) §6 له أثر. لا `UPDATE`/`DELETE` على الجدول (اختبار).

**شاشات UI مطلوبة:** ⬜ سجلّ التدقيق · ⬜ الإشعارات

## م7 — لوحة المشرف

**يعتمد على:** م6

**المُخرجات:**
- **مصفوفة دور × صلاحية** — حفظ تفاضلي، تمييز الصلاحيات الحرجة، الحارسان (§7 في [`04-rbac.md`](04-rbac.md)).
- لوحة الإعدادات بتبويبات ومحاذير على `masking.*` و`billing.*`.
- إدارة القوائم المرجعية.
- إدارة المستخدمين والشركات + التوثيق.
- عارض سجلّ التدقيق.
- تقرير الإيرادات.

**معايير القبول:** رفع رسم الكشف من ٧٥ إلى ١٠٠ ر.ق من اللوحة في أقلّ من دقيقة، بلا نشر كود، مع أثر تدقيق. **إضافة حالة وظيفية رابعة بلونها** بلا كود.

**شاشات UI مطلوبة:** ⬜ **مصفوفة الصلاحيات** · ⬜ لوحة الإعدادات · ⬜ إدارة المستخدمين · ⬜ التقارير

## م8 — الامتثال (قانون رقم 13)

**يعتمد على:** م6

**المُخرجات:**
- `consents` + موافقة **منفصلة** للبيانات ذات الطبيعة الخاصّة.
- `GET /me/data-export` (حقّ الوصول).
- `DELETE /me` → إخفاء هوية (ADR-012).
- سحب الموافقة → حذف المرفقات الحسّاسة.
- سياسة الاحتفاظ.
- إخلاء المسؤولية على شهادة حُسن السيرة + `features.good_conduct_upload = false` (ADR-013).

**معايير القبول:** التصدير يشمل كل بيانات المستخدم. الحذف يُبقي الصفوف المالية بلا معرّفات. لا نشر ملفّ بلا موافقة.

**شاشات UI مطلوبة:** ⬜ الموافقات · ⬜ تصدير/حذف البيانات
